Greedy Algorithms

Local choices that build globally optimal solutions through careful ordering, selection, and proof of correctness.

💡 Core Mechanics

  • A greedy algorithm makes the best available choice at each step without revisiting earlier decisions.
  • The choice is only reliable when the problem has the greedy-choice property and optimal substructure.
  • Common signals include interval scheduling, minimum-cost connections, deadlines, and repeatedly choosing the next most valuable or least costly option.

1. Two City Scheduling (LeetCode #1029)

Medium

A company is planning to interview 2n people. Given the array costs where costs[i] = [aCosti, bCosti], the cost of flying the i-th person to city a is aCosti, and the cost of flying the i-th person to city b is bCosti. Return the minimum cost to fly exactly n people to city a and n people to city b.

The "Aha!" Moment (Greedy Opportunity Cost / Refund Difference):
The optimal choice isn't just about picking whoever has the cheapest individual ticket to City A or City B; it's about the **relative difference** bCost - aCost (the money saved by choosing City A over City B). Sorting descending by (bCost - aCost) prioritizes sending the people with the highest financial benefit of picking A into the first half ([0, n)). The remaining half automatically goes to City B, achieving an optimal greedy solution in $O(N \log N)$ time and $O(1)$ extra space. 
/**
 * @param {number[][]} costs
 * @return {number}
 */
var twoCitySchedCost = function (costs) {
    // Sort descending by savings achieved by choosing City A over City B: (bCost - aCost)
    costs.sort((candidateA, candidateB) => {
        const savingsA = candidateA[1] - candidateA[0];
        const savingsB = candidateB[1] - candidateB[0];
        return savingsB - savingsA;
    });

    let totalCost = 0;
    const peoplePerCity = costs.length / 2;

    // First half goes to City A; second half goes to City B
    for (let i = 0; i < peoplePerCity; i++) {
        const cityACost = costs[i][0];
        const cityBCost = costs[i + peoplePerCity][1];

        totalCost += cityACost + cityBCost;
    }

    return totalCost;
};

2. Assign Cookies (LeetCode #455)

Easy

Assume you are an awesome parent and want to give your children some cookies. But, you should give each child at most one cookie. Each child i has a greed factor g[i], and each cookie j has a size s[j]. If s[j] >= g[i], we can assign the cookie j to child i. Maximize the number of content children.

The "Aha!" Moment (Greedy Two-Pointer Match):
Sort both the children by their greed factors and the cookies by their sizes in ascending order. By attempting to satisfy the **least greedy child with the smallest possible cookie** that satisfies them, you preserve larger cookies for children with higher greed factors. Advance the cookie pointer on every step, and advance the child pointer only when a valid assignment is made. 
/**
 * @param {number[]} greedFactors
 * @param {number[]} cookieSizes
 * @return {number}
 */
var findContentChildren = function(greedFactors, cookieSizes) {
    // Sort both greed levels and cookie sizes in ascending order
    greedFactors.sort((a, b) => a - b);
    cookieSizes.sort((a, b) => a - b);

    let childIndex = 0;
    let cookieIndex = 0;

    // Greedily match the smallest adequate cookie to the least greedy child
    while (childIndex < greedFactors.length && cookieIndex < cookieSizes.length) {
        if (cookieSizes[cookieIndex] >= greedFactors[childIndex]) {
            childIndex++;
        }
        cookieIndex++;
    }

    return childIndex;
};

3. Lemonade Change (LeetCode #860)

Easy

At a lemonade stand, each lemonade costs $5. Customers queue to buy from you and order one at a time. They can pay with a $5, $10, or $20 bill. You must provide the correct change to each customer so that the net transaction is $5. Return true if you can provide every customer with correct change, or false otherwise.

The "Aha!" Moment (Greedy Denomination Priority):
A $5 bill is your most versatile asset because it can give change to both $10 and $20 bills, whereas a $10 bill can only help make change for a $20 bill. When handed a $20 bill, greedily prioritize giving one $10 and one $5 rather than three $5 bills. Reserving your $5 bills keeps future change options as flexible as possible. 
/**
 * @param {number[]} customerBills
 * @return {boolean}
 */
var lemonadeChange = function(customerBills) {
    let fiveDollarCount = 0;
    let tenDollarCount = 0;

    for (const bill of customerBills) {
        if (bill === 5) {
            fiveDollarCount++;
        } else if (bill === 10) {
            if (fiveDollarCount === 0) return false;
            fiveDollarCount--;
            tenDollarCount++;
        } else {
            // Greedy choice: Prioritize giving one $10 and one $5 to conserve $5 bills
            if (tenDollarCount > 0 && fiveDollarCount > 0) {
                tenDollarCount--;
                fiveDollarCount--;
            } else if (fiveDollarCount >= 3) {
                fiveDollarCount -= 3;
            } else {
                return false;
            }
        }
    }

    return true;
};

4. Best Time to Buy and Sell Stock II (LeetCode #122)

Medium

You are given an integer array prices where prices[i] is the price of a given stock on the i-th day. On each day, you may decide to buy and/or sell the stock. You can only hold at most one share of the stock at any time. However, you can buy it and then immediately sell it on the same day. Find and return the maximum profit you can achieve.

The "Aha!" Moment (Greedy Slope Accumulation):
Because you can execute unlimited consecutive transactions, capturing every single upward price climb (prices[i] > prices[i - 1]) yields the mathematically optimal total profit. A multi-day rise from day $A$ to day $C$ ($C - A$) is identical to summing each daily ascent ($(B - A) + (C - B)$). Greedily capture every positive day-over-day price jump in a single $O(N)$ pass with $O(1)$ space. 
/**
 * @param {number[]} stockPrices
 * @return {number}
 */
var maxProfit = function(stockPrices) {
    let totalProfit = 0;

    // Accumulate every positive upward slope between adjacent days
    for (let currentDay = 1; currentDay < stockPrices.length; currentDay++) {
        const previousDayPrice = stockPrices[currentDay - 1];
        const currentDayPrice = stockPrices[currentDay];

        if (currentDayPrice > previousDayPrice) {
            totalProfit += currentDayPrice - previousDayPrice;
        }
    }

    return totalProfit;
};

5. Insert Interval (LeetCode #57)

Medium

You are given an array of non-overlapping intervals intervals where intervals[i] = [starti, endi] sorted in ascending order by starti. You are also given an interval newInterval = [start, end] that represents the start and end of another interval. Insert newInterval into intervals such that intervals is still sorted in ascending order by starti and does not have any overlapping intervals (merge overlapping intervals if necessary).

The "Aha!" Moment (Three-Phase Linear Sweep):
Because the list is already sorted, process intervals in three clean phases:
  1. Before Overlap: Collect all intervals ending strictly before the incoming interval starts (intervalEnd < targetStart).
  2. Merge Overlap: For any interval that starts before or when the incoming interval ends (intervalStart <= targetEnd), absorb it by expanding bounds: targetStart = min(...) and targetEnd = max(...).
  3. After Overlap: Push the merged interval, then append all remaining trailing intervals.
This achieves a clean $O(N)$ runtime with $O(N)$ output space in a single forward pass without re-sorting. 
/**
 * @param {number[][]} intervals
 * @param {number[]} newInterval
 * @return {number[][]}
 */
var insert = function (intervals, newInterval) {
    const mergedIntervals = [];
    let currentIndex = 0;
    const totalIntervals = intervals.length;

    let [targetStart, targetEnd] = newInterval;

    // Phase 1: Add all intervals that finish strictly before newInterval starts
    while (currentIndex < totalIntervals && intervals[currentIndex][1] < targetStart) {
        mergedIntervals.push(intervals[currentIndex]);
        currentIndex++;
    }

    // Phase 2: Merge all overlapping intervals into one expanded interval
    while (currentIndex < totalIntervals && intervals[currentIndex][0] <= targetEnd) {
        targetStart = Math.min(targetStart, intervals[currentIndex][0]);
        targetEnd = Math.max(targetEnd, intervals[currentIndex][1]);
        currentIndex++;
    }
    mergedIntervals.push([targetStart, targetEnd]);

    // Phase 3: Add all remaining intervals that start after the merged interval ends
    while (currentIndex < totalIntervals) {
        mergedIntervals.push(intervals[currentIndex]);
        currentIndex++;
    }

    return mergedIntervals;
};

6. Merge Intervals (LeetCode #56)

Medium

Given an array of intervals where intervals[i] = [starti, endi], merge all overlapping intervals, and return an array of the non-overlapping intervals that cover all the intervals in the input.

The "Aha!" Moment (Sort by Start Time + Greedy Extension):
Sorting intervals by their starting times guarantees that any overlapping intervals will be adjacent. Initialize the output list with the first interval, then compare each subsequent interval's start against the previous merged interval's end (currentStart <= lastMergedInterval[1]). Because starts are sorted, you only ever need to expand the end boundary using Math.max(lastMergedInterval[1], currentEnd). If they don't overlap, append the current interval as a new anchor point. 
/**
 * @param {number[][]} intervals
 * @return {number[][]}
 */
var merge = function (intervals) {
    if (intervals.length <= 1) return intervals;

    // Sort intervals ascending by start boundary
    intervals.sort((intervalA, intervalB) => intervalA[0] - intervalB[0]);

    const mergedIntervals = [intervals[0]];

    for (let i = 1; i < intervals.length; i++) {
        const currentInterval = intervals[i];
        const lastMergedInterval = mergedIntervals[mergedIntervals.length - 1];

        const [currentStart, currentEnd] = currentInterval;

        // Check for overlap: current interval starts before or when the last merged ends
        if (currentStart <= lastMergedInterval[1]) {
            // Expand the end boundary of the last interval
            lastMergedInterval[1] = Math.max(lastMergedInterval[1], currentEnd);
        } else {
            // No overlap: start a new interval track
            mergedIntervals.push(currentInterval);
        }
    }

    return mergedIntervals;
};

7. Partition Labels (LeetCode #763)

Medium

You are given a string s. We want to partition the string into as many parts as possible so that each letter appears in at most one part. Return a list of integers representing the size of these parts.

The "Aha!" Moment (Greedy Interval Boundary Expansion):
Every character in the current partition dictates a minimum boundary: the partition cannot end before that character's last occurrence. First, record the first and last occurrence of each character. Then, scan through the string maintaining a dynamic boundary [partitionStart, partitionEnd]. If the current index moves past partitionEnd (i > partitionEnd), the previous partition is sealed, and a new one starts. Otherwise, continually expand partitionEnd = Math.max(partitionEnd, lastOccurrence). 
/**
 * @param {string} s
 * @return {number[]}
 */
var partitionLabels = function (s) {
    const firstSeenIndices = Array(26).fill(-1);
    const lastSeenIndices = Array(26).fill(-1);

    // Precompute the first and last occurrence index for every lowercase English letter
    for (let i = 0; i < s.length; i++) {
        const charCode = s.charCodeAt(i) - 97;

        if (firstSeenIndices[charCode] < 0) {
            firstSeenIndices[charCode] = i;
        }
        lastSeenIndices[charCode] = i;
    }

    const partitionSizes = [];
    let partitionStart = 0;
    let partitionEnd = 0;

    for (let currentIndex = 0; currentIndex < s.length; currentIndex++) {
        // Current index passed the boundary of the previous segment: finalize and reset
        if (currentIndex > partitionEnd) {
            partitionSizes.push(partitionEnd - partitionStart + 1);
            partitionStart = currentIndex;
            partitionEnd = currentIndex;
        }

        const charCode = s.charCodeAt(currentIndex) - 97;

        partitionStart = Math.min(partitionStart, firstSeenIndices[charCode]);
        partitionEnd = Math.max(partitionEnd, lastSeenIndices[charCode]);
    }

    // Flush the final remaining partition
    if (partitionStart <= partitionEnd) {
        partitionSizes.push(partitionEnd - partitionStart + 1);
    }

    return partitionSizes;
};

8. Non-overlapping Intervals (LeetCode #435)

Medium

Given an array of intervals intervals where intervals[i] = [starti, endi], return the minimum number of intervals you need to remove to make the rest of the intervals non-overlapping. Note that intervals which touch at a point (e.g., [1, 2] and [2, 3]) are non-overlapping.

The "Aha!" Moment (Greedy Earliest End-Time / Interval Scheduling):
Minimizing removals is mathematically equivalent to maximizing the count of mutually non-overlapping intervals. To leave as much room as possible for future intervals, sort the intervals in ascending order by their end boundary (endi). Track the end marker of the last retained interval. If the next interval starts before this marker (start < lastEnd), an overlap occurs, so increment the removal count. Otherwise, retain it and update lastEnd = currentEnd. 
/**
 * @param {number[][]} intervals
 * @return {number}
 */
var eraseOverlapIntervals = function (intervals) {
    if (intervals.length <= 1) return 0;

    // Greedily sort ascending by end time to finish intervals as early as possible
    intervals.sort((intervalA, intervalB) => intervalA[1] - intervalB[1]);

    let lastAcceptedEnd = -Infinity;
    let removalCount = 0;

    for (let i = 0; i < intervals.length; i++) {
        const [currentStart, currentEnd] = intervals[i];

        // Strict inequality: intervals touching at a boundary point do NOT count as overlap
        if (currentStart < lastAcceptedEnd) {
            // Overlap detected: greedily discard the interval that finishes later
            removalCount++;
        } else {
            // No overlap: retain this interval and update the boundary marker
            lastAcceptedEnd = currentEnd;
        }
    }

    return removalCount;
};

9. Task Scheduler (LeetCode #621)

Medium

Given a characters array tasks, representing the tasks a CPU needs to do, where each letter represents a different task. Tasks could be done in any order. Each task is done in one unit of time. For each cycle of CPU, the CPU could complete either one task or just be idle. However, there is a non-negative integer n that represents the cooldown period between two same tasks (the same task must be separated by at least n intervals). Return the least number of units of times that the CPU will take to finish all the given tasks.

The "Aha!" Moment (Greedy Chunk Scheduling / Bottleneck Formula):
The execution time is bottlenecked entirely by the task with the highest frequency (maxFrequency). Arrange the most frequent tasks first to create maxFrequency - 1 chunks of length n + 1. The final chunk only contains tasks that tie for the highest frequency (maxFrequencyCount). The baseline formula is (maxFrequency - 1) * (n + 1) + maxFrequencyCount. If there are enough other tasks to fill all idle slots, no idle time is needed, so the total time will simply be tasks.length. Thus, the answer is Math.max(calculatedCycles, tasks.length). 
/**
 * @param {character[]} tasks
 * @param {number} n
 * @return {number}
 */
var leastInterval = function(tasks, n) {
    const taskFrequencies = Array(26).fill(0);
    let maxFrequency = 0;

    // Count frequency of each task and identify the maximum frequency
    for (let i = 0; i < tasks.length; i++) {
        const charCode = tasks[i].charCodeAt(0) - 65;
        taskFrequencies[charCode] += 1;
        maxFrequency = Math.max(maxFrequency, taskFrequencies[charCode]);
    }

    // Count how many tasks share the maximum frequency
    let maxFrequencyCount = 0;
    for (let i = 0; i < 26; i++) {
        if (taskFrequencies[i] === maxFrequency) {
            maxFrequencyCount++;
        }
    }

    // Calculate required cycles based on the bottleneck chunks
    const chunkCount = maxFrequency - 1;
    const chunkSize = n + 1;
    const minimumCycles = (chunkCount * chunkSize) + maxFrequencyCount;

    // If remaining tasks exceed the idle slots created, no idle cycles are needed
    return Math.max(minimumCycles, tasks.length);
};

10. Gas Station (LeetCode #134)

Medium

There are n gas stations along a circular route, where the amount of gas at the i-th station is gas[i]. You have a car with an unlimited gas tank and it costs cost[i] of gas to travel from the i-th station to its next (i + 1)-th station. You begin the journey with an empty tank at one of the gas stations. Given two integer arrays gas and cost, return the starting gas station's index if you can travel around the circuit once in the clockwise direction, otherwise return -1. If there exists a solution, it is guaranteed to be unique.

The "Aha!" Moment (Net Gain Invariant & Greedy Reset):
Two mathematical invariants drive this solution:
  1. Global Feasibility: If the total gas gained across all stations is greater than or equal to the total cost (totalTank >= 0), a valid circular route is mathematically guaranteed to exist.
  2. Greedy Reset: If your running tank drops into negative territory while traveling from station $A$ to station $B$ (currentTank < 0), then no station between $A$ and $B$ can be a valid starting point either, as they would start with even less accumulated gas. Reset the candidate starting station to i and clear currentTank = 0.
This allows finding the unique starting index in a single pass in $O(N)$ time and $O(1)$ space. 
/**
 * @param {number[]} gas
 * @param {number[]} cost
 * @return {number}
 */
var canCompleteCircuit = function(gas, cost) {
    let startingStation = 0;
    let currentTank = 0;
    let totalTank = 0;

    for (let i = 0; i < gas.length; i++) {
        // If the tank goes negative, previous candidate start points cannot reach station i
        if (currentTank < 0) {
            startingStation = i;
            currentTank = 0;
        }

        const netGasGain = gas[i] - cost[i];
        currentTank += netGasGain;
        totalTank += netGasGain;
    }

    // A valid circuit exists if and only if total gas acquired covers total travel cost
    return totalTank >= 0 ? startingStation : -1;
};

11. Car Pooling (LeetCode #1094)

Medium

There is a car with a capacity of capacity empty seats. The vehicle only drives east (i.e., it cannot turn around and drive west). You are given the integer capacity and an array trips where trips[i] = [numPassengersi, fromi, toi] indicates that the i-th trip has numPassengersi passengers and the locations to pick them up and drop them off are fromi and toi respectively. The locations are given as the number of kilometers due east from the car's initial starting location. Return true if it is possible to pick up and drop off all passengers for all the given trips, or false otherwise.

The "Aha!" Moment (Difference Array / Prefix Sum Timeline):
Instead of updating passenger counts across every kilometer in each trip interval (which would cost $O(\text{trips} \times \text{distance})$), treat the route as a Difference Array. At pickup kilometer pickupLocation, add passengers (+numPassengers); at dropoff kilometer dropoffLocation, subtract them (-numPassengers) because passengers disembark before or at that exact marker. A single running prefix sum sweep across the timeline reveals the exact occupancy at every point in $O(N + D)$ time, failing immediately if occupancy ever exceeds capacity. 
/**
 * @param {number[][]} trips
 * @param {number} vehicleCapacity
 * @return {boolean}
 */
var carPooling = function (trips, vehicleCapacity) {
    // Problem constraint: 0 <= from_i < to_i <= 1000
    const passengerDeltas = Array(1001).fill(0);

    // Record net passenger change at pickup and dropoff milestones
    for (let i = 0; i < trips.length; i++) {
        const [passengerCount, pickupLocation, dropoffLocation] = trips[i];

        passengerDeltas[pickupLocation] += passengerCount;
        passengerDeltas[dropoffLocation] -= passengerCount;
    }

    let currentPassengerCount = 0;

    // Sweep linearly across the timeline to compute prefix occupancy
    for (let kilometer = 0; kilometer <= 1000; kilometer++) {
        currentPassengerCount += passengerDeltas[kilometer];

        if (currentPassengerCount > vehicleCapacity) {
            return false;
        }
    }

    return true;
};

12. Candy (LeetCode #135)

Hard

There are n children standing in a line. Each child is assigned a rating value given in the integer array ratings. You are giving candies to these children subjected to the following requirements: each child must have at least one candy, and children with a higher rating get more candies than their neighbors. Return the minimum number of candies you need to have to distribute the candies to the children.

The "Aha!" Moment (Two-Pass Bidirectional Greedy):
A child has two independent neighbor constraints: the left neighbor and the right neighbor. Instead of resolving both simultaneously, decouple them into two passes:
  1. Left-to-Right Pass: Ensure every child with a higher rating than their left neighbor receives more candies (leftToRight[i] = leftToRight[i - 1] + 1).
  2. Right-to-Left Pass: Ensure every child with a higher rating than their right neighbor receives more candies (rightToLeft[i] = rightToLeft[i + 1] + 1).
Taking the maximum of both allocations for each child (Math.max(leftToRight[i], rightToLeft[i])) guarantees that both neighbor conditions are satisfied simultaneously while minimizing total candies in $O(N)$ time and $O(N)$ space. 
/**
 * @param {number[]} ratings
 * @return {number}
 */
var candy = function (ratings) {
    const childCount = ratings.length;
    const leftToRightCandies = Array(childCount).fill(1);
    const rightToLeftCandies = Array(childCount).fill(1);

    // Pass 1: Satisfy left-neighbor condition
    for (let i = 1; i < childCount; i++) {
        if (ratings[i] > ratings[i - 1]) {
            leftToRightCandies[i] = leftToRightCandies[i - 1] + 1;
        }
    }

    // Pass 2: Satisfy right-neighbor condition
    for (let i = childCount - 2; i >= 0; i--) {
        if (ratings[i] > ratings[i + 1]) {
            rightToLeftCandies[i] = rightToLeftCandies[i + 1] + 1;
        }
    }

    let totalCandies = 0;

    // Combine both constraints by taking the maximum requirement for each child
    for (let i = 0; i < childCount; i++) {
        totalCandies += Math.max(leftToRightCandies[i], rightToLeftCandies[i]);
    }

    return totalCandies;
};

The "Aha!" Moment (Peak & Valley Counting / $O(1)$ Space):
Instead of allocating arrays, model the ratings sequence as a mountain terrain of rising slopes (up), falling slopes (down), and flat plateaus:
  1. Base Allocation: Start by giving every child 1 candy (totalCandies = ratings.length).
  2. Slopes: An uphill climb of length k requires accumulating $1 + 2 + \dots + k$ additional candies. A downhill slope behaves symmetrically.
  3. The Peak Collision: The mountain peak is shared by both the ascending and descending slopes, meaning its height was counted twice. We subtract Math.min(upSlopeLength, downSlopeLength) to adjust the peak candy count to whichever slope was taller.
This resolves the problem in a single pass in $O(N)$ time and strictly $O(1)$ auxiliary space. 
/**
 * @param {number[]} ratings
 * @return {number}
 */
var candy = function (ratings) {
    const totalChildren = ratings.length;
    let totalCandies = totalChildren; // Baseline: every child receives at least 1 candy
    let currentIndex = 1;

    while (currentIndex < totalChildren) {
        // Flat plateau: equal adjacent ratings reset slope dependency
        if (ratings[currentIndex] === ratings[currentIndex - 1]) {
            currentIndex++;
            continue;
        }

        let upSlopeLength = 0;
        // Count consecutive ascending ratings
        while (currentIndex < totalChildren && ratings[currentIndex] > ratings[currentIndex - 1]) {
            upSlopeLength++;
            totalCandies += upSlopeLength;
            currentIndex++;
        }

        let downSlopeLength = 0;
        // Count consecutive descending ratings
        while (currentIndex < totalChildren && ratings[currentIndex] < ratings[currentIndex - 1]) {
            downSlopeLength++;
            totalCandies += downSlopeLength;
            currentIndex++;
        }

        // Deduct the duplicate peak allocation, keeping the higher slope's requirement
        totalCandies -= Math.min(upSlopeLength, downSlopeLength);
    }

    return totalCandies;
};
