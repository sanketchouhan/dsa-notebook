Backtracking

An algorithmic technique for finding all (or some) solutions by exploring a tree of choices and discarding invalid paths.

💡 The Backtracking Mental Model

  • State Space Tree: Think of the problem as a tree where every node represents a partial solution state, and every branch represents a decision choice.
  • The Core Template: Every problem follows a strict 3-step loop structure: Choose an option, Explore recursively down that path, and Unchoose (undo) that option to reset the state for the next branch.
  • Pruning: If a partial path violates problem constraints, abandon it immediately (return early). This prevents traversing entire dead-end subtrees.

📝 Implementation Logs

1. Subsets - Iterative Choice Pattern (LeetCode #78)

Medium

An alternative implementation of the Power Set problem. Instead of using a binary inclusion/exclusion decision tree, this approach utilizes a loop to dynamically branch out for every remaining available choice in the array.

The "Aha!" Moment: In this style of backtracking, every state visited is a valid subset, so we push a snapshot to our results immediately upon entering the function. The for loop acts as a breadth-explorer that picks an element, recursively drills down to find all subsets containing that element, and then pops it to slide over to the next choice. 
var subsets = function(nums) {
    const res = [];

    const backtrack = (start, subset) => {
        // Every single step down the decision path is a valid combination state
        res.push([...subset]);

        // Iterate through all remaining available candidate choices
        for (let i = start; i < nums.length; i++) {
            subset.push(nums[i]);      // Choose: Take the current element
            
            backtrack(i + 1, subset);  // Explore: Move pointer forward to avoid reuse
            
            subset.pop();              // Unchoose: Clean up state for the next loop iteration
        }
    };

    backtrack(0, []);
    return res;
};

2. Combinations (LeetCode #77)

Medium

Given two integers n and k, return all possible combinations of k numbers chosen from the range [1, n]. You may return the answer in any order.

The "Aha!" Moment: This is a direct extension of the loop-based Subsets pattern, but with a structural twist: our base case acts as a size gate. Instead of collecting every partial state, we only take a snapshot when the path.length === k. Furthermore, we can prune branches early if the remaining available numbers in the loop aren't enough to fill the path up to size k. 
var combine = function(n, k) {
    const result = [];

    const backtrack = (path, start) => {
        // Base Case: If the path reaches our exact constraint size k, log it and return
        if (path.length === k) {
            result.push([...path]);
            return;
        }

        // Standard Backtracking Loop: Explore numbers from 'start' to 'n'
        for (let i = start; i <= n; i++) {
            path.push(i);          // Choose: Add candidate number

            backtrack(path, i + 1); // Explore: Advance start index to avoid duplicates

            path.pop();           // Unchoose: Remove number and backtrack
        }
    };

    backtrack([], 1); // Initialization starting with an empty path and index 1
    return result;
};

3. Permutations (LeetCode #46)

Medium

Given an array nums of distinct integers, return all the possible permutations. You can return the answer in any order.

The "Aha!" Moment: Unlike Subsets or Combinations where elements are picked sequentially from a moving start index to avoid duplicates, Permutations care about element order. This means every recursive path must scan the entire array from i = 0 to evaluate all possible rearrangements. To prevent using the same array element multiple times down a single linear path branch, check if the value is already present using path.includes(nums[i]) before processing the choice. 
var permute = function(nums) {
    const result = [];

    const backtrack = (path) => {
        // Base Case: If our path contains all numbers, a full arrangement configuration is complete
        if (path.length === nums.length) {
            result.push([...path]);
            return;
        }
        
        // Loop always begins at 0 because order variations matter (e.g., [1, 2] vs [2, 1])
        for (let i = 0; i < nums.length; i++) {
            // Constraint check: Skip element if it's already active in our local branch track
            if (!path.includes(nums[i])) {
                path.push(nums[i]);     // Choose: Place current number down
                
                backtrack(path);        // Explore: Recurse with loop resetting back to index 0
                
                path.pop();             // Unchoose: Extract element and backtrack
            }
        }
    };

    backtrack([]);
    return result;
};

4. Subsets II - Handling Duplicates (LeetCode #90)

Medium

Given an integer array nums that may contain duplicates, return all possible subsets (the power set). The solution set must not contain duplicate subsets. Return the solution in any order.

The "Aha!" Moment: When an array contains duplicate items, branching without a rule generates twin execution sub-trees. To elegantly bypass duplicate combinations without using slow hashing structures, sort the input array first. Once sorted, matching elements sit side-by-side. Inside your exploration loop, apply the skip rule: if (i > start && nums[i] === nums[i - 1]) continue;. This permits an identical value to be used down a deeper vertical path branch, but completely halts processing the exact same number horizontally across the same loop level! 
var subsetsWithDup = function (nums) {
    const result = [];

    // CRITICAL: Sort the array first to bring duplicate elements side-by-side
    nums.sort((a, b) => a - b);

    const backtrack = (path, start) => {
        // Collect every unique combination state generated along the path
        result.push([...path]);

        for (let i = start; i < nums.length; i++) {
            // Prune duplicate paths: Skip the element if it matches the previous item, 
            // BUT only if it's NOT the first choice in the current loop frame (i > start)
            if (i > start && nums[i - 1] === nums[i]) {
                continue;
            }

            path.push(nums[i]);      // Choose
            backtrack(path, i + 1);  // Explore
            path.pop();              // Unchoose
        }
    };

    backtrack([], 0);
    return result;
};

5. Combination Sum (LeetCode #39)

Medium

Given an array of distinct integers candidates and a target integer target, return a list of all unique combinations of candidates where the chosen numbers sum to target. You may return the combinations in any order. The same number may be chosen from candidates an unlimited number of times.

The "Aha!" Moment: To allow the same number to be reused infinitely down a single decision path, do not advance your pointer to i + 1 when recursing. Instead, pass the current loop index i down to the next frame. To optimize constraint checking, pass a tracking sum variable that subtracts the chosen value at each step (Top-Down Deduction). If the sum drops below zero (sum < 0), prune the entire sub-tree immediately. 
var combinationSum = function (candidates, target) {
    const result = [];

    const backtrack = (path, start, remainingSum) => {
        // Base Case / Pruning: Sub-tree exceeds target bound
        if (remainingSum < 0) return;

        // Base Case: Target perfectly matched
        if (remainingSum === 0) {
            result.push([...path]);
            return;
        }

        for (let i = start; i < candidates.length; i++) {
            path.push(candidates[i]); // Choose
            
            // Explore: Pass 'i' instead of 'i + 1' to allow element reuse
            backtrack(path, i, remainingSum - candidates[i]); 
            
            path.pop(); // Unchoose
        }
    };
    
    backtrack([], 0, target);
    return result;
};

6. Combination Sum II - Unique Combinations (LeetCode #40)

Medium

Given a collection of candidate numbers candidates and a target number target, find all unique combinations in candidates where the candidate numbers sum to target. Each number in candidates may only be used once in the combination. Note: The solution set must not contain duplicate combinations.

The "Aha!" Moment: This problem merges two distinct blueprints: the element deduction constraints from Combination Sum I and the horizontal duplicate pruning from Subsets II. First, **sort the candidates** to group duplicates. Inside the loop, block twin branches at the same recursion depth using if (i > start && candidates[i] === candidates[i - 1]) continue;. To ensure an element is only used once per path, advance the pointer to i + 1 during exploration. 
var combinationSum2 = function (candidates, target) {
    const result = [];
    
    // Sort array first to position duplicates adjacently for easy pruning
    candidates.sort((a, b) => a - b);

    const backtrack = (path, start, remainingSum) => {
        // Base Case / Pruning: Exceeded target bound
        if (remainingSum < 0) return;
        
        // Base Case: Target perfectly matched
        if (remainingSum === 0) {
            result.push([...path]);
            return;
        }

        for (let i = start; i < candidates.length; i++) {
            // Horizontal duplicate pruning: Skip the same element value across the same loop frame
            if (i > start && candidates[i - 1] === candidates[i]) {
                continue;
            }

            path.push(candidates[i]); // Choose
            
            // Explore: Pass 'i + 1' to ensure each array index is only used once
            backtrack(path, i + 1, remainingSum - candidates[i]);
            
            path.pop(); // Unchoose
        }
    }
    
    backtrack([], 0, target);
    return result;
};

7. Combination Sum III (LeetCode #216)

Medium

Find all possible combinations of k numbers that add up to a number n, given that only numbers from 1 to 9 can be used, and each combination should be a unique set of numbers.

The "Aha!" Moment: This variation introduces a dual-constraint gate. Instead of iterating through an input array, the search space is static and fixed: numbers 1 through 9. The base case fires exactly when path.length === k, and we only capture the path snapshot if our top-down deduction matches target perfectly (remainingSum === 0). 
var combinationSum3 = function (k, n) {
const result = [];

const backtrack = (remainingSum, path, start) => {
  // Base Case Constraint 1: Path has reached the required size k
  if (path.length === k) {
      // Base Case Constraint 2: Target sum is perfectly met
      if (remainingSum === 0) {
          result.push([...path]);
      }
      return; // Terminate branch exploration regardless of sum status
  }
  
  // Loop is hard-bounded between 'start' and 9 based on problem constraints
  for (let i = start; i <= 9; i++) {
      path.push(i); // Choose
      
      // Explore: Advance to 'i + 1' to guarantee unique number selections
      backtrack(remainingSum - i, path, i + 1); 
      
      path.pop(); // Unchoose
  }
}

backtrack(n, [], 1);
return result;
};

8. Letter Combinations of a Phone Number (LeetCode #17)

Medium

Given a string containing digits from 2-9 inclusive, return all possible letter combinations that the number could represent. Return the answer in any order. A mapping of digits to letters (just like on the telephone buttons) is provided below.

The "Aha!" Moment: Instead of looping through the same array over and over, the loop choices at each level are **dynamically determined by the current digit**. The recursion depth is tracked by an index pointer moving through the digits string. At each frame, we look up the corresponding character string from our telephone map (e.g., 2 -> "abc") and loop through *only* those specific characters.

// Visual Phone Keypad Tree Branching Structure / Mapping State Space Tree 

var letterCombinations = function (digits) {
// Edge Case: Return empty array immediately if input is empty
if (!digits.length) return [];

// Map configuration mimicking physical phone keypad interfaces
const letters = {
  2: "abc",
  3: "def",
  4: "ghi",
  5: "jkl",
  6: "mno",
  7: "pqrs",
  8: "tuv",
  9: "wxyz"
};

const result = [];

const backtrack = (path, index) => {
  // Base Case: If pointer equals input length, path string is complete
  if (index === digits.length) {
      result.push(path.join(""));
      return;
  }

  // Dynamically fetch character choices matching the current active digit
  const choices = letters[digits[index]];

  // Loop bounds are isolated strictly to the matched digit letters length
  for (let i = 0; i < choices.length; i++) {
      path.push(choices[i]);     // Choose
      
      backtrack(path, index + 1); // Explore: Advance index to load next digit mapping
      
      path.pop();                 // Unchoose
  }
};

backtrack([], 0);
return result;
};

9. Permutations II - Unique Permutations (LeetCode #47)

Medium

Given a collection of numbers, nums, that might contain duplicates, return all possible unique permutations in any order.

The "Aha!" Moment: Permutations require tracking order variations, which means we must scan all available candidates at each frame rather than using a forward-moving index pointer. To prevent duplicate configurations when the input array contains repeating elements, sort the numbers first. Then, dynamically pass a sliced, shrinking array of remaining choices to the next recursive frame. Within the step loop, skip identical adjacent candidate elements using if (i > 0 && choices[i] === choices[i - 1]) continue; to shut down duplicate horizontal search branches entirely. 
var permuteUnique = function (nums) {
    const result = [];
    
    // Sort array first to position duplicates adjacently for easy pruning
    nums.sort((a, b) => a - b);

    const backtrack = (path, choices) => {
        // Base Case: If the path matches the length of the input, the full permutation is captured
        if (path.length === nums.length) {
            result.push([...path]);
            return;
        }

        // Iterate strictly over the remaining available options passed to this frame
        for (let i = 0; i < choices.length; i++) {
            // Horizontal duplicate pruning: Skip identical adjacent choice numbers on the same level
            if (i > 0 && choices[i] === choices[i - 1]) {
                continue;
            }

            path.push(choices[i]); // Choose
            
            // Explore: Slice out the selected element to forward a shrinking window of valid remaining choices
            backtrack(path, [...choices.slice(0, i), ...choices.slice(i + 1)]);
            
            path.pop(); // Unchoose
        }
    }

    backtrack([], nums); // Initial kickoff with full array loaded as choice targets
    return result;
};

The "Aha!" Moment (Used Array vs. Slicing Optimization):
Slicing the choices array on each recursive frame forces $O(N)$ array buffer creation per level. To optimize this to a constant $O(N)$ global auxiliary space, replace slicing with a single **used boolean array** to track elements in-place by flipping flags (true on choose, false on unchoose).

When skipping duplicates with this array, the condition if (i > 0 && nums[i] === nums[i - 1] && !used[i - 1]) continue; isolates and prunes redundant horizontal sibling branches. If used[i - 1] is true, the duplicate is active in a deeper vertical path (valid sequence like [1, 1, 2]). If used[i - 1] is false, that duplicate has already been fully explored and popped out at the current level, meaning processing it again would launch an identical, redundant search tree. 
var permuteUnique = function (nums) {
    const result = [];
    const used = new Array(nums.length).fill(false);
    
    // Sort array first to position duplicates adjacently for easy pruning
    nums.sort((a, b) => a - b);

    const backtrack = (path) => {
        // Base Case: Path length matches input size
        if (path.length === nums.length) {
            result.push([...path]);
            return;
        }

        // Always scan the entire array from index 0 for permutation positioning
        for (let i = 0; i < nums.length; i++) {
            // Constraint Check 1: Skip if the element is active in the current vertical branch
            if (used[i]) continue;

            // Constraint Check 2: Prune redundant horizontal sibling branches
            if (i > 0 && nums[i] === nums[i - 1] && !used[i - 1]) {
                continue;
            }

            // Choose: Flag element as active and push to path
            used[i] = true;
            path.push(nums[i]);

            // Explore down the branch
            backtrack(path);

            // Unchoose: Extract element and lower the usage flag for the next loop sibling
            path.pop();
            used[i] = false;
        }
    };

    backtrack([]);
    return result;
};

10. Palindrome Partitioning (LeetCode #131)

Medium

Given a string s, partition s such that every substring of the partition is a palindrome. Return all possible palindrome partitioning of s.

The "Aha!" Moment (String Partitioning Pattern):
Instead of choosing index items, this pattern slices dynamic substring prefixes. The loop index i dictates the length of our current candidate slice (0 to i). If the substring is not a palindrome, we prune the branch immediately. If it is valid, we pass the leftover remainder string down to the next frame. The base case hits successfully when the remainingString is fully consumed and empty.

// Visual String Partitioning State Tree / Substring Palindrome Validation Diagram 

var partition = function (s) {
    const result = [];

    const backtrack = (path, remainingString) => {
        // Base Case: If no characters remain, a complete valid partition configuration is achieved
        if (!remainingString.length) {
            result.push([...path]);
            return;
        }

        // Loop represents the length of the substring slice we are carving out
        for (let i = 1; i <= remainingString.length; i++) {
            const choice = remainingString.substring(0, i);

            // Prune branch: Skip if the current structural slice is not a palindrome
            if (!isPalindrome(choice)) {
                continue;
            }

            path.push(choice); // Choose
            
            // Explore: Pass the trimmed remainder string down to the next frame
            backtrack(path, remainingString.substring(i));
            
            path.pop(); // Unchoose
        }
    }

    backtrack([], s);
    return result;
};

// Two-pointer linear verification subroutine
const isPalindrome = (s) => {
    let start = 0;
    let end = s.length - 1;

    while (start < end) {
        if (s[start] !== s[end]) {
            return false;
        }
        start++;
        end--;
    }
    return true;
};

The "Aha!" Moment (Index Pointers Optimization):
Passing string slices like remainingString.substring() down recursive frames forces $O(N)$ memory allocations at every branch level. We can optimize this to $O(1)$ string copy overhead by operating exclusively on a single immutable reference of string s combined with an execution pointer start. The exploration loop boundary runs from i = start to s.length, passing i + 1 down to the next frame as the subsequent structural boundary. This shifts our validation phase to a simple zero-allocation index-based window lookup. 
var partition = function (s) {
    const result = [];
    const path = [];

    const backtrack = (start) => {
        // Base Case: If the start pointer reaches the end of the string, the entire text has been cleanly partitioned
        if (start === s.length) {
            result.push([...path]);
            return;
        }

        // 'i' marks the ending boundary of our targeted substring choice window
        for (let i = start; i < s.length; i++) {
            // Validate the index window bounds directly on the global string
            if (!isPalindrome(s, start, i)) {
                continue;
            }

            // Choose: Carve the confirmed substring slice out to log in the current branch path
            path.push(s.substring(start, i + 1));
            
            // Explore: Shift the next start frame pointer immediately past our current end boundary marker
            backtrack(i + 1);
            
            // Unchoose: Extract the slice to clear out the state for the next horizontal sibling index check
            path.pop();
        }
    };

    backtrack(0);
    return result;
};

// In-place pointer validation checker running at absolute O(1) auxiliary memory allocations
const isPalindrome = (str, left, right) => {
    while (left < right) {
        if (str[left] !== str[right]) {
            return false;
        }
        left++;
        right--;
    }
    return true;
};
